## 1. 拆解原则

MVP-1 的目标是"用 1 家真实公司把规格 → 对话 → 报价 → 确认发送 → 计费这条链路完整跑通"。
按**风险 × 规格完备度**排序施工：

| 优先级 | 判据 | 对应模块 |
|---|---|---|
| 最高 | 错了会直接产生对外的错误金额 | 定价引擎、Money、FR-8 校验 |
| 高 | 以后再补代价极大（数据迁移） | 规格版本化、报价快照、租户隔离 |
| 高 | 合规/安全底线 | 发送闸门、鉴权、发送前披露 |
| 中 | 规格明确、可独立测试 | 脸型文法、@ 路由、计费去重与争议 |
| 后置 | 依赖上面全部就绪 | LLM 编排、户型图、EstimateDraft |

**为什么先做定价而不是先做对话**：对话层是可替换的外壳，定价层是不可替换的地基；
而且定价是纯函数、可穷举测试，能在没有任何 LLM 调用的情况下建立正确性基线。

### 顺带修掉的 v0.3 遗留问题

- `MAX_FETCH_BYTES` 限流失效（原先 `await res.arrayBuffer()` 之后才切片，整个响应体已进内存）→ 改为流式读取并提前中断。
- 无私网地址过滤（SSRF）→ 加 `blockedUrlReason` 护栏，拦截环回/私网/CGNAT/云元数据端点（`169.254.169.254`）。
- 模块级全局单例状态与多租户冲突 → 全部改为按会话/租户隔离。
- 完全无鉴权 → 加了账号中间件（MVP 级，非生产方案）。
- `confirm: true` 请求体即可发信 → 改为服务端状态机。
- 客户端群发 UI（与 CASL 冲突）→ 删除；`email.ts` 一并移除。

### 关键测试（不是凑数的那种）

- **定价**：多价格组取价、价格矩阵空洞拒绝、定额与百分比混合的顺序无关性、分档折扣边界、`stackable:false` 互斥、运费阈值边界、QC 非复合 QST、NS 税率变更前后、13 省全覆盖、纯函数性。
- **FR-8**：型号真实但价格编造 → 价格被丢弃，最终金额来自规格库（`test/e2e.test.ts`）。
- **闸门**：直接 POST `/send` 带 `confirm:true` → **409 拒绝**（`test/http.test.ts`）。
- **租户**：恒真谓词、显式点名别家 id 均漏不出数据；跨租户读报"不存在"而不泄露存在性。
- **渲染**：12" 柜与 36" 柜的门缝**都是 0.25"**——这条断言就是否决"归一化 symbol + scale"方案的依据。
- **计费**：同会话重发 → 邮件照发、计费抑制；争议期内出账被拒。

### 关键测试

- **装箱**：恰好整除无剩余；同填充度下柜子更少者胜出（72" → 2×36 而不是 6×12）；
  剩余超出填缝条能力时标为不可行；1/4 英寸精度。
- **排布**：只用规格库里真实存在的型号与离散尺寸；柜体不超墙、互不重叠；
  窗下无吊柜；局部重算不动其他墙段。
- **视图**：四张图都是合法 SVG 且**不含 `transform="scale"`**；正视图标注台面 36"、
  俯视图地柜层 24"/吊柜层 12"、侧视图踢脚 4-1/2" 与吊柜底边 54"。
- **比价**：含税口径混用时必须警告并指向"未税小计"列。
- **HTML 邮件**：四层兜底齐备；营销类邮件的退订链接**必须同时出现在纯文本与 HTML 里**
  （只放一处，另一版的收件人就无从退订）。
- **可复制性**：第二家公司不给覆盖表时脸型规则命中 0 且全部进待确认；给了覆盖表则 16/16 命中。

### 实现过程中发现并修掉的缺陷

- **视图渲染器从 SKU 码重新推导脸型**，忽略了规格库里已存好的 `faceTemplateId`——
  用自有命名体系的公司（靠覆盖表映射）会全部退化成空白矩形。改为 `Placement`
  携带 `faceTemplateId`，渲染优先用它。
- XML 文本节点里把 `"` 转成 `&quot;`，让满是英寸符号的尺寸标注变得难读且难测。
  文本节点只需转义 `&`、`<`、`>`。
- `pickWallCabinetHeight` 的规则原先没写明"留 6" 顶线空间"，导致 96" 层高的选择
  依赖阅读者猜测。已在注释里把三档层高的推导写清。
