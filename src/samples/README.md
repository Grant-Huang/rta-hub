# 厨房户型模板库 (Kitchen Layout Templates)

## 概述

本目录包含 5 种北美住宅常见厨房户型的**手绘风格插图**，供客户开场时参考——
"我家大概长这样"。这些图片只是**给客户看的示意图**，本身不含任何具体尺寸，
系统也不会从这些图片里读取或抽取任何数字。

选中某个户型（点按钮或打字说"L-shape"）后，系统只会按该户型的**结构**
（有几段墙、墙的罗盘方位、墙与墙是否转角相接、是否有岛台）建一个空的墙面
骨架——这是客户选择这个户型本身就已经告诉我们的事实。**除此之外不预填任何
数值**：墙长、层高、门窗/上下水/燃气/强电的位置和宽度，一律留空，等客户
自己填写，或者客户上传一张真实户型图/手绘图让系统识图读取。

> 为什么不能"预填一个常见值"？因为那不是这位客户家里的真实数据——哪怕
> 这个数字在北美厨房里很常见（比如墙长 144"、层高 96"），也不代表客户家
> 就是这个尺寸。把"常见"当成"已知"去预填，等于让系统替客户猜测，猜错了
> 客户还容易被"确认"这个措辞误导，以为是自己已经提供过的数据。

## 必填与可选参数

以下所有参数**均由客户提供**（对话里报出实测数字，或上传真实户型图/手绘图
让系统识图），系统不提供任何默认值：

### 必填（出第一版设计前必须拿到）

- **每段墙的长度**（英寸）
- **层高**（英寸）
- **上下水/水槽位置**：在哪面墙、距墙角大概多少

### 必填、但可以先说"稍后决定"（不阻断出第一版设计，但会阻断问风格/预算/省份）

- **燃气接口位置**（没有可以说"没有燃气，用电"）
- **强电接口位置**（接冰箱/烤箱，没有燃气时也接灶具）
- **岛台尺寸**（选了带岛台的户型时；没有可以说"不做岛台"）

### 可选（有就记录，没有也不影响出图）

- **窗户位置与宽度**（没有可以说"没有窗"）
- **门洞位置与宽度**

## 户型列表（仅供客户挑选参考图，不含尺寸）

### 1. 单壁型 (One-Wall / Straight Kitchen)

**文件：** `one-wall-kitchen-floorplan.png`

**特点：**
- 单面墙布局，最节省空间，适合小户型
- 常见于：公寓 (Condo)、小型单元

**适用场景：**
- 开放式厨房
- 工作室/单身公寓
- 空间受限的厨房改造

---

### 2. U 型 (U-Shaped Kitchen)

**文件：** `u-shaped-kitchen-floorplan.png`

**特点：**
- 三面墙形成U型（West / North / East）
- 台面空间最大化

**适用场景：**
- Single Family House
- Townhouse
- 中大型厨房

---

### 3. L 型 + 岛台 (L-Shape + Island Kitchen)

**文件：** `l-island-kitchen-floorplan.png`

**特点：**
- L型墙面（North / East）+ 中央岛台
- 现代住宅最流行布局
- 岛台可用于备餐、用餐、收纳

**适用场景：**
- 开放式厨房
- 现代 Single Family House
- 需要社交空间的厨房

---

### 4. 双排/走廊型 (Galley / Corridor Kitchen)

**文件：** `galley-kitchen-floorplan.png`

**特点：**
- 两面平行墙（North / South），中间留通道，不转角相接
- 高效利用窄长空间

**适用场景：**
- Townhouse（联排别墅）
- 窄长型厨房
- 需要最大化存储空间

---

### 5. L 型标准 (L-Shaped Kitchen)

**文件：** `sample-floorplan.png` / `sample-floorplan-minimal.png`

**特点：**
- 两面墙形成L型（North / East）
- 灵活度高，适应性强
- 可选是否加岛台

**适用场景：**
- 最通用的厨房布局
- 各种房型均适用

---

## 图例说明 (Legend)

所有插图使用统一图例，方便客户照着这个图例手绘自己家的户型：

- **窗户 (Window)**: ═══ (平行线)
- **门 (Door)**: ⌒ (弧线，显示开启方向)
- **上下水/水槽 (Plumbing/Sink)**: ○○ (两个圆圈)
- **岛台 (Island)**: ⟋⟋⟋ (斜线填充矩形)
- **墙体 (Wall)**: ▬▬ (粗黑线)
- **指北针 (North)**: ↑N (带方位标识)

## 使用说明

### 客户使用
1. 选择最接近自己厨房的户型（只是挑一张示意图/一个形状名，不代表任何尺寸）
2. 系统按这个户型建好墙面结构后，逐项提供实际尺寸：每段墙的长度、层高、
   上下水/窗/门/燃气/强电的位置
3. 也可以直接上传自己家的户型图/手绘图，系统会尝试识图读取真实尺寸
   （仍然需要客户逐项确认识图结果）

### 前端集成
```typescript
import { INTAKE_SAMPLES } from './samples/catalog.ts';

// 获取所有户型示意图
const floorplanSamples = INTAKE_SAMPLES.filter(s => s.role === 'floorplan');

// 显示给用户选择
<SampleGallery samples={floorplanSamples} />
```

### 安全验证
- 所有文件名通过 `isAllowedSampleFile()` 白名单验证
- 禁止路径穿越攻击
- 仅允许 `/src/samples/` 目录下的文件

## NKBA 标准参考（用于净空校验，不是预填尺寸）

系统在排布校验环节（而不是户型采集环节）会依据 NKBA (National Kitchen &
Bath Association) 标准做净空检查，例如：

- **工作通道**: 最小 42"
- **工作三角**: 冰箱-水槽-灶台总距 12'-26'
- **水槽与洗碗机**: 距离 ≤36"
- **灶台净空**: 左右各 ≥12"
- **冰箱净空**: 开门后 ≥15"

这些是排布阶段用来检查"客户提供的真实尺寸装不装得下"的约束规则，不是
户型采集阶段的默认/预填数值。

## 贡献指南

### 新增户型插图要求
1. **风格一致**: 手绘风格，清晰可读
2. **图例完整**: 按上面的图例说明标注墙体/窗/门/上下水/岛台的位置，
   但**不要**在插图里写死具体尺寸数字——这只是给客户看的形状示意图
3. **文件命名**: `{type}-kitchen-floorplan.png`
4. **更新 catalog.ts**: 添加中英文标签
5. **更新 templates.ts**: `walls`/`kind`/`startsAtCorner` 描述的是墙面
   结构，客户选形状即可确认，可以自由登记；`length`/`ceilingHeight`/
   `features` 这些数值字段**只会**被视觉识图模块用作"读不出来时的建议值"
   （见 `src/floorplan/template-match.ts`），绝不能被 `applyFloorplanTemplate`
   （客户没上传图、只是点选形状）这条路径拿去预填——新增字段/改动前请确认
   没有破坏这个边界
